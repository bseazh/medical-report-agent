# 敏医康健康评估工作台 MVP To-do List

> 目标：先跑通一个真实病例的完整闭环：病例截图/PDF上传 → 解析 → 关键数据提取 → 人工审核 → 功能医学矩阵 → 健康建议 → 可编辑 PPT 导出。

## 一、MVP 建议

首期建议控制在“本地单机、单用户、项目制、人工审核后导出”的范围内：

- 使用 Node.js 作为本地工作台服务层；
- 使用 MinerU 处理 PDF；
- 使用 DeepSeek 文本模型处理摘要、分类和建议草稿；
- 使用 DeepSeek 视觉模型处理固定格式病例截图；
- 使用 JSON 文件或 SQLite 保存项目数据，暂不引入复杂数据库；
- 保持现有 14 页 PPT 结构，先做模板填充，不做自由排版；
- 先以王玮项目作为唯一验收样例；
- 所有 AI 结果必须经过人工确认后才能进入 PPT；
- 所有关键结论必须保留来源文件和页码；
- 暂不做账号、云部署、加密、药物剂量、自动复查周期和知识库建设。

## 五、建议的第一轮开发任务

第一轮只做以下闭环，不同时开发全部功能：

1. 项目创建和项目目录；
2. 批量上传 1 份 PDF；
3. MinerU 解析并保存结果；
4. 展示解析文本和页码；
5. 提取 3～5 个关键异常项；
6. 人工修改并保存；
7. 输出结构化 JSON。

第一轮跑通后，再增加截图视觉解析；然后增加矩阵；最后增加 PPT。这样每一步都有可验证产物，出现问题时容易定位。

## 六、完成定义（Definition of Done）

一个模块只有同时满足以下条件，才算完成：

- 页面可以操作；
- 数据可以保存；
- 失败状态可以显示；
- 结果可以人工修改；
- 关键数据有来源；
- 不会把密钥写入仓库；
- 有一个真实样例通过；
- GitHub 和服务器都能同步运行。
