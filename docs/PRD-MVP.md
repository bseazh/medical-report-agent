# 敏医康健康评估工作台 MVP PRD

## 1. 产品定位

本产品是运行在本地电脑上的内部 Web 工作台，用于把一个病例项目中的病例截图和检测 PDF 整理为：

1. 结构化病例资料；
2. 可追溯的关键指标与异常项；
3. 功能医学矩阵与摘要；
4. 人工审核后的健康建议；
5. 可编辑的指导方案 PPT。

MVP 只验证“一个真实病例完整跑通”。系统输出是健康信息整理和健康管理辅助内容，不构成医疗诊断、治疗或用药处方。

## 2. MVP 范围

| 范围 | MVP 定义 |
|---|---|
| 运行方式 | 本地 Node.js 服务，浏览器访问 localhost |
| 项目管理 | 项目列表、新建、打开、删除；每个项目独立文件夹 |
| 截图输入 | 固定诊所系统截图；视觉模型提取病例字段、症状、既往史、过敏史、用药史、时间线 |
| PDF 输入 | MinerU 解析固定版式报告；首批覆盖现有 4 类报告，架构允许新增报告适配器 |
| AI 分析 | DeepSeek 负责结构化补充、摘要、矩阵草稿和建议草稿 |
| 人工审核 | 病例字段、指标、来源、矩阵和建议均可审核/修改；确认后才可生成 PPT |
| 输出 | 结构化 JSON、来源目录、矩阵视图、可编辑 PPT |
| 历史记录 | 保留项目、导出文件、模型输出、提示词版本和操作日志 |
| 暂不实现 | 账号权限、云部署、加密、录音转写、全量知识库、药物剂量、自动复查周期、无限格式兼容 |

## 3. 用户流程

```text
新建项目 → 上传截图/PDF → 截图视觉解析 + PDF MinerU 解析
→ 统一结构化 → 关键异常/关键正常项提取 → 人工审核病例和指标
→ DeepSeek 生成矩阵与建议草稿 → 人工审核建议
→ 填充 PPT 模板 → 预览/编辑 → 导出 PPT → 写入日志
```

```json
{

  "patientId": "patient-id",

  "createdAt": "ISO-8601",
  "updatedAt": "ISO-8601",
  "files": [],
  "exports": [],
  "auditLog": []

```

### 4.2 来源与指标

所有模型结论必须能回溯到来源文件和页码；截图来源可记录图片名和字段名。

```json
{
  "name": "钛",
  "value": "28.06",
  "unit": "μg/g",
  "reference": "<4.0",
  "status": "显著偏高",
  "reportType": "营养与毒性元素分析（头发）",
  "source": { "file": "report.pdf", "page": 3, "locator": "表格/钛" },
  "reviewStatus": "待审核"

```

### 4.3 病例截图固定字段

姓名、性别、年龄、就诊时间、科室、医生、主诉、现病史、既往史、家族史、过敏史、个人史、出生史、月经/婚育史、体格检查、望闻切诊、诊断、诊疗项目、既往用药、症状时间线。

## 5. 解析和模型边界

### 5.1 MinerU

MinerU 只处理 PDF，输出 Markdown/JSON 及页码信息。首期重点提取基础信息、异常指标、关键正常指标、分级、报告结论和来源位置，不要求复制整份报告。

### 5.2 视觉模型

视觉模型处理病例截图，输出固定 JSON。模型无法确定的字段必须返回空值并标记 `待人工确认`，不得猜测。

### 5.3 DeepSeek

DeepSeek 可生成摘要、指标关联、矩阵草稿和建议草稿，但不能绕过审核进入 PPT。每次调用保存模型名、提示词、原始响应、结构化响应、时间和人工修改记录。模型名和 API 地址放在环境变量/配置中，支持后续切换到 `deepseek-v4-flash-vision-exp` 等视觉模型。

### 5.4 确定性规则

确定性规则优先负责：数值/单位/参考范围、异常判断、食物不耐受等级、来源绑定、审核状态和页面路由。指标到功能维度的映射先配置化，模型只生成候选内容。

## 6. 功能医学矩阵模型

《功能医学案例.pptx》反向得到四种视图：

### 6.1 总矩阵

维度固定为：前置因素、诱发因素、介质因素、同化代谢、代谢转换与消除、结构完整性、防御与修护、传递系统、传输系统、能量生成、睡眠与放松、运动与活动、营养和水分、压力、人际社交关系。

每个维度字段：维度说明、病例背景、相关检测项目、关键异常项、关键正常项、综合评估、建议方向、来源列表、审核状态。无异常显示“未见明显异常”；资料不足显示“暂无足够资料，待人工补充”。

### 6.2 核心根源机制

字段：核心根源标题、根源节点、因果节点、结果节点、支持指标、综合结论、来源列表、审核状态。首期可用文本/节点列表表达，后续再做图形化。

### 6.3 三因素分析

分为 Antecedents（前置因素）、Triggers（诱发因素）、Mediators（介质因素）三列；每列包含分类标题、事实条目、支持来源和审核状态。

### 6.4 健康事件时间线

字段：时间、事件标题、事实描述、相关症状/诊断、支持来源、审核状态。时间不确定时保留原文表达，例如“童年”“近年”“当前”。

## 7. 健康建议模块

建议必须分为：

1. 必须回避；
2. 建议调整；
3. 可选建议。

首期页面包括饮食回避、食物替代、每餐饮食、运动、饮水、减压、营养支持。营养支持暂不生成药物、补充剂剂量或疗程；干预周期和复查周期先作为可选人工填写字段，不由模型自动推导。

## 8. PPT 模板

保持当前 14 页结构：封面、称谓、核心功能失衡 3 页、饮食回避、食物替代、每餐饮食、运动、饮水、减压、干预方案 2 页、结语。功能取证图首期保留占位页或跳过。模板文本保持可编辑；内容溢出时允许新增同类页面。无异常维度保留“未见明显异常”。

## 9. 工作台页面

| 页面 | 功能 |
|---|---|
| 项目列表 | 新建、搜索、打开、删除历史项目 |
| 项目资料 | 上传截图/PDF、查看文件和解析状态 |
| 解析结果 | 查看原文、结构化字段、指标和来源目录 |
| 人工审核 | 编辑病例字段、指标、异常等级、来源和时间线 |
| 矩阵与建议 | 查看/编辑四类矩阵、三类建议和模型原始输出 |
| PPT 导出 | 预览、编辑、导出 PPT，保留导出历史 |
| 设置 | API 地址、模型名、提示词模板和本地数据目录 |

状态统一为：未开始、处理中、待人工审核、已确认、存在异常、已导出、失败。

## 10. MVP 验收

使用王玮项目作为首个验收样例：33 张截图和 4 份 PDF 均可归档；病例字段可人工确认；关键指标含文件/页码来源；四类矩阵可生成并编辑；建议审核后可填充 14 页 PPT；PPT 文本可编辑；删除、导出和操作日志可用。

## 11. 需求变更边界

新增报告机构/版式、字段、矩阵维度、建议规则、输出格式、账号权限、云部署、接口、知识库或药物剂量，均作为新增需求。首期完成后再逐项评估。
